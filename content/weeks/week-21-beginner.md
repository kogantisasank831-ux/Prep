## Before you start

Basic Python functions and dictionaries are enough. This route explains the
performance terms before using them. The [production route]({{ '/weeks/week-21/' | relative_url }})
adds tail latency, cache invalidation, concurrency limits and rollout evidence.

The [Week 21 assessment]({{ '/assessments/week-21/' | relative_url }}) checks
understanding with ten balanced questions.

## The kitchen analogy

Imagine a kitchen with a small station and a large station. The large station
can handle difficult orders but costs more time and resources. Sending every
order there works, but wastes capacity. Sending every order to the small station
can reduce quality.

A router sends simple classification and extraction work to the small station
and difficult recommendations to the large one. If the estimated quality is
below the floor, the request moves to the large station. That is model routing.

## Learn seven measurements

| Term | Plain meaning |
| --- | --- |
| input tokens | pieces of instructions and context sent to the model |
| output tokens | pieces generated by the model |
| TTFT | wait until the first generated token arrives |
| end-to-end latency | wait until the full answer finishes |
| quality floor | minimum accepted evaluation score |
| request budget | maximum accepted estimated cost for one call |
| cache hit | a valid earlier answer reused without another model call |

The lab uses made-up units so results stay stable. They are not prices.

## Trim only what you can lose

Mark context as required or optional before trimming it. A repeated low-ranked
passage may be optional. The output schema, safety instruction and supporting
clause may be required. The simulator removes only declared optional tokens.

**Check yourself:** if removing a passage could change the correct answer, do
not call it optional without evaluation evidence.

## Two calls can sometimes run together

If address extraction and language detection do not depend on each other, they
can run at the same time. Their combined wait is close to the slower call. If a
recommendation needs the extracted address, it must wait.

Parallel work still uses capacity. A real service needs a limit so a traffic
burst does not start thousands of calls at once.

## Cache with the full identity of the answer

The same text can mean different things for different tenants, prompt versions
or model versions. The lab cache key includes all three plus a data key. A hit
for tenant A cannot be returned to tenant B.

Recommendations are not cached in the demo. Real semantic caches need even more
care because “similar” questions are not always equivalent.

## Streaming changes the wait you notice

Streaming shows the beginning of an answer early. That improves TTFT, but the
full answer may still take the same time. Report both numbers. Do not label a
stream as complete before validation finishes.

## Run the experiment

~~~shell
python -m labs.week_21.demo compare
python -m labs.week_21.demo smoke
python -m pytest tests/test_week21_optimization.py -q
~~~

Find the four routed decisions in the JSON. Explain why the complex
recommendation uses the large model, why one extraction loses only optional
context and why the second exact cache lookup costs zero synthetic units.

## Completion checklist

- Explain tokens, TTFT and completion latency in your own words.
- Route by task and keep a quality floor.
- Trim only declared optional context.
- Run independent calls together only when safe.
- Include tenant and versions in a cache key.
- Say clearly that fixture values are not real prices or benchmarks.
