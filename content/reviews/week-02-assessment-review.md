## Contracts and implementation

| Requirement | Implementation |
| --- | --- |
| Random ten-question paper | Two items of each format without duplicates; shuffled questions/options; reproducible seed/version |
| Scores out of 100 | Existing exact single/short/full-set multiple scoring; matching 2.5 per pair; SQL 2 per passed dataset |
| Actual syntax evaluation | PostgreSQL parses and executes each submitted query; no keyword/reference-text matching |
| SQL cases | Five independently initialized datasets: split receipts, boundary/decimal/zero values, missing facts, ties/duplicates and empty tables |
| Result comparison | Column names/order, ordered row values, duplicate multiplicity, NULL distinction and exact canonical decimals |
| External workspace | Optional db<>fiddle PostgreSQL 18 link; visible copyable schema/example data; no automatic code transfer or external score import |
| Pages hosting | Static assets; pinned PGlite downloads on demand without a server, API key or build step |
| Lifecycle | Fresh worker per solution; 45-second loading and 5-second whole-run execution deadlines; Stop terminates worker |
| Failure handling | Infrastructure/fixture failures leave marks pending; retry preserves submitted source; SQL answer failures lose checked marks |
| Existing experience | Saved progress, blank print, share links, explanations and JSON result export retained |
| Navigation | Enable Week 2 and add one link paragraph in each lesson; preserve all original lesson text and SQL |

The bank declares code_language sql with a shared small schema and five named
fixtures. An absent language remains Python for the unchanged Week 1 bank.
Validation rejects unsupported languages, absent schema/example data, unknown
fixture names and malformed expected result shapes. The page chooses the
language's worker and instructions. Week 1's Python worker/runner and bank are
unchanged.

PGlite 0.5.11 is pinned on the documented jsDelivr ESM distribution. The npm
package declares Apache-2.0 licensing; code loads from the CDN rather than being
vendored. It requires no paid service or tracked package/build dependency. The
tested engine reports PostgreSQL 18.6 (PGlite 0.5.11); the procurement lab retains
its existing independently pinned image.

Each SQL case recreates the practice schema, runs one learner statement in a
read-only transaction and rolls back. Trusted fixture failures propagate as
unavailable, never as a learner failure. The prepared single-statement API
rejects multiple statements. Decimal/bigint parsers retain strings, avoiding
floating-point tolerance or loss beyond JavaScript safe integer precision.
Dates compare as ISO dates.

The small assessment schema deliberately differs from the full lab. Its
zero-quantity fixture tests denominator guards; the page/schema state that the
main lab requires positive PO quantities. Tasks state current-status eligibility
and date cutoffs explicitly; no lifecycle history reconstruction is implied.

Independent expectations were calculated from synthetic row data with Python
Decimal/Fraction arithmetic and event ordering, then stored as result rows
rather than generated by executing reference SQL. Anchors include 870 kg
accepted and 130 kg remaining on the 1,000 kg example line. Its USD 1,560 open
value plus USD 50 on another line gives USD 1,610 across example USD orders.
A later price can be lower than an older price, so MAX(price) loses marks in the
latest-observation exercise. Same-day receipts test deterministic event order.

PGlite has one connection. Two-session locking experiments remain in the full
lab; concurrency and privileges are evaluated here with reasoning questions.
This is practice with public keys and locally editable scores, not an
authenticated exam service. Five public cases provide feedback, not a proof for
every possible dataset. Worker termination bounds time, not memory. Loading
depends on network/CDN/browser support. No learner identity or central score
store is added. SQL runs on the device; an external workspace receives only
what a learner chooses to enter there.

Rollback is an ordinary revert of this feature commit. Attempts stay namespaced
by week and bank version. Later bank edits must increment the version.
