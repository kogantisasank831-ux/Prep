# Week 24 project-storytelling contracts — revision 1

Source: `Path.md` Week 24. This lab turns declared project evidence into three
practice depths. It never invents a metric, silently changes attribution or
claims that presence of evidence proves its truth.

| ID | Effective rule and acceptance |
| --- | --- |
| W24-BR1 | Maintain one evidence record as the sole source for 2-minute, 10-minute and deep-dive stories. |
| W24-BR2 | Separate situation, task, personal role, team ownership, actions, decisions, results, failure, limitation and reflection. |
| W24-FR1 | Require every metric to include a displayed value, provenance and individual/team/organization attribution. |
| W24-FR2 | Require every decision to name its reason, rejected alternative and consequence. |
| W24-FR3 | Keep the 2-minute pack concise; add decision, failure, leadership and reflection in the 10-minute pack; add remaining actions, decisions and metrics only in the deep dive. |
| W24-FR4 | Preserve declared metric attribution in generated claims. Never rewrite a team or organization outcome as an individual result. |
| W24-FR5 | Score six visible dimensions from 0–2: structure, ownership, evidence, decisions, failure and reflection. A readiness pass requires 10/12 and explicit team ownership. |
| W24-SR1 | Treat external truth verification, confidential-data review and employer approval as separate gates before using any story in a real interview. |
| W24-NFR1 | Identical evidence and depth produce identical ordered claims without a model, network, clock or random source. |
| W24-ER1 | Test strict evidence, provenance, required core fields, three-depth ordering, attribution preservation, readiness gaps, determinism and all CLI paths. |

## Honest attribution

“I built” should describe work the candidate personally owned. “We achieved”
should describe a team result. Organization-level business outcomes need even
more care: explain how they were measured and which part the project plausibly
influenced. A number without its baseline, time window and source is a prompt for
verification, not a stronger claim.

The synthetic demo intentionally labels its metrics as fixture results. Learners
must replace the complete evidence record with facts they can defend; they must
not reuse the demo's numbers as personal experience.

## Accepted limitations

- The fixture is fictional and proves only transformation and rubric behavior.
- Estimated minutes label narrative depth; the code does not measure speaking
  speed or guarantee duration.
- Provenance is recorded but not independently verified.
- The rubric checks presence and specificity, not communication quality,
  technical correctness or interviewer judgment.
- The lab does not store recordings, résumés, employer data or personal secrets.
